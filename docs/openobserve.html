Observability foundation

OpenObserve onboarding, access, and recovery

LocalLink automates the safe infrastructure boundary. Applications keep a provider-neutral OpenTelemetry interface, while OpenObserve supplies the workspace backend and private UI.

Install or adopt

locallink extension plan observability
locallink extension apply observability

# Only when the resulting plan contains a fresh route token:
locallink extension apply-routes private-edge "<token-from-plan>"

The plan inspects Docker state, persistent storage, /healthz, authenticated API access, local port binding, OTLP values, and the Private Edge route. Planning never writes files or changes containers.

Apply preserves an existing OpenObserve image, data volume, username, password, organization, and stream. A new installation receives an available loopback port, an official OSS image, a named volume, and generated credentials stored only in the local .env. The file is restricted to mode 0600.

Access model

  • OPENOBSERVE_ENDPOINT is the loopback UI/API origin used by local tools.
  • OPENOBSERVE_OTLP_BASE_URL is http://127.0.0.1:<port>/api/<organization> with no trailing slash.
  • OTLP/HTTP exporters append /v1/logs, /v1/metrics, or /v1/traces.
  • The authorization header is Basic <OPENOBSERVE_ACCESS_KEY_B64>; a stream-name header selects the stream.
  • The Tailscale+Caddy URL is for people opening the UI. Local applications should normally ingest through loopback.

Credential recovery

OpenObserve uses ZO_ROOT_USER_EMAIL and ZO_ROOT_USER_PASSWORD when creating the root user on first startup. Changing those environment values later is not a safe account reset. If the dashboard reports stale credentials, LocalLink leaves the data and account untouched.

  1. Back up the OpenObserve volume and metadata before account recovery.
  2. Prefer changing a known password through the OpenObserve UI.
  3. If locked out, follow OpenObserve’s documented root reset command inside the existing container using an explicitly chosen new password.
  4. Update OPENOBSERVE_USERNAME, OPENOBSERVE_PASSWORD, and the derived OPENOBSERVE_ACCESS_KEY_B64 together.
  5. Run locallink extension plan observability and require credentialState: valid before recreating or publishing the service.

Do not delete the volume or reinstall OpenObserve to fix a login problem. A container restart does not erase a correctly mounted volume.

What still belongs to the application

LocalLink provides the endpoint and authorization contract. The application chooses its service name and which signals to emit. Custom spans, metrics, log correlation, sampling, and sensitive-data filtering remain application decisions. Use standard OTEL_* variables so the backend can be replaced without rewriting instrumentation.
