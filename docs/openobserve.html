Observability foundation

OpenObserve and OpenTelemetry onboarding

LocalLink automates the safe infrastructure boundary. Applications send vendor-neutral OTLP to a workspace-local OpenTelemetry Collector, while OpenObserve supplies the persistent backend and private UI.

Install or adopt

locallink extension plan observability
locallink extension apply observability

# Only when the resulting plan contains a fresh route token:
locallink extension apply-routes private-edge "<token-from-plan>"

The plan inspects Docker state, persistent storage, /healthz, authenticated API access, collector configuration and health, the last matching end-to-end delivery verification, local port bindings, OTLP values, and the Private Edge route. Planning never writes files or changes containers.

Apply preserves an existing OpenObserve image, data volume, username, password, organization, and stream. A new installation receives available loopback ports, official OpenObserve and OpenTelemetry Collector images, a named volume, and generated credentials stored only in the local .env. The file is restricted to mode 0600.

Access model

  • OTEL_EXPORTER_OTLP_ENDPOINT is the workspace collector’s loopback OTLP/HTTP origin.
  • Docker applications map LOCALLINK_OTEL_DOCKER_ENDPOINT into their standard OTEL_EXPORTER_OTLP_ENDPOINT; container loopback must not be used to reach the collector.
  • OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf gives applications a standard, backend-neutral export contract.
  • Each application sets its own OTEL_SERVICE_NAME and chooses which signals and instrumentation to enable.
  • OPENOBSERVE_ENDPOINT and OPENOBSERVE_OTLP_BASE_URL are backend values for LocalLink and the collector, not normal application configuration.
  • .locallink/otel-collector.yaml references OPENOBSERVE_ACCESS_KEY_B64; it never contains the actual credential. Docker injects that value at runtime.
  • Apply sends a timestamped canary to /v1/logs and searches for it through the authenticated OpenObserve API. The local verification record contains endpoints, organization, stream, and time—but no secret.
  • The Tailscale+Caddy URL is for people opening the OpenObserve UI. OTLP ingestion and collector health are never published through Private Edge.

Credential recovery

OpenObserve uses ZO_ROOT_USER_EMAIL and ZO_ROOT_USER_PASSWORD when creating the root user on first startup. Changing those environment values later is not a safe account reset. If the dashboard reports stale credentials, LocalLink leaves the data and account untouched.

  1. Back up the OpenObserve volume and metadata before account recovery.
  2. Prefer changing a known password through the OpenObserve UI.
  3. If locked out, follow OpenObserve’s documented root reset command inside the existing container using an explicitly chosen new password.
  4. Update OPENOBSERVE_USERNAME, OPENOBSERVE_PASSWORD, and the derived OPENOBSERVE_ACCESS_KEY_B64 together.
  5. Run locallink extension plan observability and require credentialState: valid before recreating or publishing the service.

Do not delete the volume or reinstall OpenObserve to fix a login problem. A container restart does not erase a correctly mounted volume.

What still belongs to the application

LocalLink provides the collector endpoint and transport contract. The application chooses its service name and which signals to emit. Custom spans, metrics, log correlation, sampling, and sensitive-data filtering remain application decisions. Use standard OTEL_* variables so the collector or backend can be replaced without rewriting instrumentation.
